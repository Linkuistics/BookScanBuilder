### F1 — Medium: the human question does not itemise what the finite interim removes, replaces and leaves

- **Where:** baseline-delivery-k56 (its filename position shifted by the
  integration insert) lines 37-47 (recommendation rationale), `01-DONE-planning--baseline-review-k55.md:127-131`
  (boundary table) and `:159-172` (closure table), `docs/specs/rotation-processor.md:36-41`.
- **Evidence:** the recommendation is justified by removing "the first server/UI/
  HTTP authentication/live-browser-freeze/Stop subsystem". Against k53's twelve
  Done when bullets (`_baseline-review.md:20-91`) that removal reaches only parts
  of bullet 4 (token/Host/Origin, authenticated Stop, live frozen commit 6),
  bullet 5 (server readiness/terminal events) and bullet 10 (the test-owned
  browser driver). Bullets 1, 2, 6, 7, 8, 9, 11 and 12 are untouched, and bullet
  3's roster/full/native views must now be generated rather than served. The
  interim also introduces surface the original did not have: a generated view
  packet, finite decision commands, a finite event/result vocabulary and
  view-to-revision identity, all of which k56 itself says are undesigned
  (`k56:53-56`). k55's closure table states what remains owned, not which part
  of each bullet is removed, replaced or new.
- **Consequence:** the human is asked to permit a public interface change for a
  size benefit that is stated only as a subsystem name. Without the per-bullet
  accounting they cannot see that the heaviest bullets (7, 8, 9, 11) are
  unchanged, so the reply may over- or under-weight the staging.
- **Remedy (checkable):** k56's question must carry a short per-criterion
  accounting of the twelve bullets as removed / replaced by new designed surface /
  unchanged, plus the list of new surface. Keep it qualitative; assert no
  implementation size.

### F2 — Medium: the browser-first branch names no concrete alternatives

- **Where:** `k56:4-10` (Goal: "or retain browser-first and resolve a different
  explicit session boundary") and `:82-86`; `k55:143-149`.
- **Evidence:** k55's table found no smaller same-interface first build, and k57's
  charter and k55 row 7 exclude input/assessment deferral without agreement.
  What remains for a "no" answer is a relaxation of a rule (e.g. accept k53 as a
  multi-session node with internal milestones despite the root's no-horizontal-
  child rule), or a signed-scope deferral, or the finite interim again. None is
  listed. The branch says only "resolve the specific remaining boundary with the

- **Consequence:** a "no" reply leaves k53 oversized with no named next act, and
  the requirements session must invent the alternatives live, which is the
  open-ended handback `execute.md` rules out.
- **Remedy:** enumerate the two or three concrete browser-first resolutions in
  k56's question with a recommended one and its evidence, and state what each
  would waive.

### F3 — Medium: the interim-to-final command and event transition is not in the design's must-settle list

- **Where:** `k56:72-81`, `docs/specs/rotation-processor.md:30-41`,
  `_baseline-review.md:44-48` (bullet 5), `.grove/_BRIEF.md:785-792`.
- **Evidence:** v2's `process` imports, assesses and *serves* local review; `review`
  resumes it; Stop exits 0; `--json` is versioned JSON Lines for server events.
  k56's design list names finite commands/help/results, view-to-revision identity,
  dispositions/acknowledgement, lock/signal/publication lifecycle and previous-
  project reader compatibility. It does not name whether interim commands reuse
  `process`/`review` with different blocking semantics, whether they survive after
  the browser lands, or how the event vocabulary extends. The root's k52 rule
  (`_BRIEF.md:790-792`) assumes one vocabulary that later stages extend compatibly.
  A search of k56, k55 and the k53 brief for the transition found nothing.
- **Consequence:** shell loops are the root's headline use. If interim `process`
  exits and the browser stage's `process` blocks, loops written against the first
  silently hang; if names differ, a permanent public surface appears that no
  charter owns. The planner would have to invent the policy.
- **Remedy:** add "interim-to-final command names, blocking semantics, event/result
  schema versions and whether the interim commands survive" to k56's design
  must-settle list and to the consequences disclosed in the question.

### F4 — Low: the design leaf has no stated branch for "still not session-sized"

- **Evidence:** k56 correctly says the recommendation is not evidence that the
