## Findings

### F1 — Medium: B's single-session assessment depends on F seams no F Done-when requires

**Evidence.** k53's browser size assessment calls B "a bounded single-session
extension" because F hands over "verified... operations, private substitution
seams, fixtures and a reproducible six-case runner". F's charter asks only for
"reusable responsible operation seams ... without designing a plugin framework"
(k63 last Done-when). B's charter then needs: operations run under a lock the
server already holds ("No borrowed/reacquired second lock"); the same replay
boundary keyed by a browser request ID plus displayed identity instead of a
receipt file; presentation-neutral tile/panel/label data to serve in a page; F's
fault/six-case runner driven through a server; and a reusable framebuffer
measurement. Nothing in F's Done-when makes any of these true or checkable.

**Failure.** F ships one-shot CLI operations that each open the lock, key replay
on receipt files and emit PDF packets. B's bootstrap then finds the reuse it was
assessed on absent, so the "remaining inventory" becomes a refactor of F plus
the server, and the size question is answered only after F is retired.

**Minimal remedy.** Add one F Done-when bullet naming those five properties,
each with a construction check inside F (no HTTP needed): an operation invoked
with caller-held ownership succeeds while a second in-process acquisition is
busy; an envelope with request ID and displayed identity commits and replays
before currency like a receipt; one view manifest feeds packets; the runner takes
the front end as a parameter; the display-measurement procedure is recorded as
reusable. Not a new leaf, and not a size claim for B.

### F2 — Medium: F's continuation protocol has no stall bound and no interleaving rule

**Evidence.** driver.md: an exit-signal ending relaunches on the next leaf
whatever the harness status, and F stays first live. k63 allows "Context
continuation may be signalled while F stays live" with its task-owned jj change
open across sessions, but states no progress condition or cap. commit.md: a later
session's edits are snapshotted into whatever change is open at `@`.

**Failure.** (a) A continuation that makes no progress (toolchain blocker,
unanswerable native question) signals continuation again and relaunches
indefinitely, spending a session each time. (b) Any leaf inserted ahead of F,
for example a human-inserted policy or boundary-question leaf, runs with F's
partial work in `@`, and its describe/new seals F's work into that other task.

**Minimal remedy.** Add to F's continuation paragraph: a session that adds no new
evidence, diff or logged decision must not signal continuation; it records the
blocker in the log and stops without the exit signal (or asks inside the
session). Anything F externalises is `leaf-add`ed after F; a leaf inserted ahead
begins with `jj new` over F's open change so F's work stays in its own change.

### F3 — Low: F's native-display demonstration is ordered after its two largest milestones

**Evidence.** The ordinary-viewer 1:1 hypothesis (Preview PNG density from
measured backing scale) and an observed framebuffer measurement are in
milestone 3 (k63 table). Nothing shows that an AFK session on this Mac can drive
the viewer and capture the framebuffer; earlier sessions used a VM and the
Chrome connector for documentation only. The spec makes a failure a scoped human
question that keeps F live.

**Failure.** The failure surfaces after milestones 1-2 are built, with F blocked
on a human answer and B and k54 behind it.

**Minimal remedy.** Add to milestone 1's exit evidence a bounded probe independent
of the renderer: a synthetic ruler PNG at the proposed density in the actual
viewer with a recorded framebuffer measurement, or the named missing mechanism.
Same check, earlier; it adds no leaf.

### F4 — Low: three recorded-field items from original criteria 1-2 appear in neither charter

**Evidence.** Criterion 1 says "record ... hints"; criterion 2 says assessment on
"an analysis copy, retaining angle/status/ratio/settings/regions". k63 says hints
are "optional advisory only", never that they are recorded as provenance; it does
not mention the analysis copy or retained regions. The ownership map's row 2
lists "settings/version/status/angle/ratio" only. B inherits none.

**Failure.** An implementer following the charters alone can retain the angle
without its regions or assess the live render instead of an isolated copy, and
the omission passes F's Done-when.

**Minimal remedy.** Add those three phrases to k63's import/assessment bullet and
row 2 of the ownership map. Checkable: the saved assessment record carries
regions and the hint provenance; the helper runs on a copy.
